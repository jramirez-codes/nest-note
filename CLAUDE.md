# NestNote

React Native note-taking app (the "pad") + Go companion server (`server/`) that runs
Claude-powered subjects/orchestrator, with a documentation site in `site/`
(Astro + Starlight).

## Docs must stay in sync with the product

**Any change to product functionality is not done until the matching docs in
`site/src/content/docs/` are updated in the same branch/PR.** Treat the docs
update as part of the change itself, not a follow-up task.

After changing behavior, always:

1. Identify which docs pages describe the touched behavior (map below).
2. Update those pages — wording, flags, command names, screenshots references,
   defaults, prerequisites — so they describe the *new* behavior.
3. If the change adds a genuinely new feature with no home, add a new page
   (see `site/src/content/docs/contributing/docs.md` for conventions).
4. If nothing in the docs is affected (pure refactor, tests, tooling), say so
   explicitly in your summary — "no docs impact" — so the check is visible.

### Code area → docs pages

| Code touched | Docs to check/update |
|---|---|
| `src/` (app screens, editor, capture, dictation, storage) | `start/the-pad.md`, `start/editor-bundle.md`, `commands/capture.mdx`, `commands/writing.mdx`, `architecture/editor.md`, `architecture/storage.md` |
| `webview-editor/` | `start/editor-bundle.md`, `architecture/editor.md` |
| `server/` (Go companion server) | `server/setup.md`, `server/native-setup.md`, `server/remote-access.md`, `architecture/overview.md` |
| `server/auth.go`, `server/pairing.go`, `server/tlscert.go` | `server/pairing.md`, `server/security.md` |
| Server CLI flags (`server/main.go`, `server/cmd/`) | `server/flags.md` — every flag added/renamed/removed/defaults-changed must appear here |
| `server/ws.go`, protocol/message types | `architecture/protocol.md` |
| `server/agent.go`, `server/claude.go`, orchestrator/subjects | `commands/index.mdx`, `commands/projects.mdx`, `commands/admin.mdx`, `architecture/overview.md` |
| `server/dashboard.go` | `commands/dashboard.mdx` |
| Voice/system commands (triggers, spoken commands) | `commands/` pages covering that command |
| Install/build steps, `package.json` scripts, platform setup | `start/install.md`, `contributing/workflow.md` |
| Repo structure moves/renames | `contributing/repo-layout.md` |

When in doubt, grep the docs for the feature name/flag before finishing:

```bash
grep -ri "<feature-or-flag>" site/src/content/docs/
```

### Docs conventions (summary)

- Pages live under `site/src/content/docs/`; frontmatter needs `title` and
  `description`. `commands/`, `architecture/`, `contributing/` sidebars are
  autogenerated; `Get started` and `Companion server` are explicit in
  `site/astro.config.mjs` — adding a page there needs a sidebar-config line.
- Capability warnings (server required, `-allow-*` flags) are **never**
  hand-written: declare `requiresServer` / `requiresFlag` in frontmatter and
  render the shared `<Requires />` component (page must be `.mdx`). A stale
  `-allow-*` warning is a security problem.
- Full conventions: `site/src/content/docs/contributing/docs.md`.

### Verifying docs changes

```bash
cd site
npm run dev    # http://localhost:4321/nest-note/
npm run build  # catches broken links / schema errors
```
