## `/record`

> Record microphone audio — keeps going in the background; tap to stop.

```text
/record
```

Starts recording the device microphone. Recording **continues in the
background**, so you can leave the app or lock the phone and it keeps going.
Tap the card to stop.

Clip metadata is stored in the `recordings` table; the app holds a wake lock
while recording so the OS doesn't suspend it.

:::note[On-device]
`/record` captures audio locally and needs no server. What you subsequently do
with a clip may.
:::

:::caution[Android only]
Recording is backed by a native module that exists for Android only — capture
runs in a microphone-typed foreground service (hence the ongoing notification),
and export writes into the shared audio library via MediaStore. On an iOS build
the card reports that the recorder module isn't present. See
[Android & iOS](../start/platforms.md).

On Android, `/record` captures **this device's microphone only** — your own side
of a call, never the remote party, which the OS reserves for system apps.
:::

## `/talk`

> Chat about a subject — the orchestrator keeps its notes updated as you talk.

```text
/talk storage-migration I think FTS5 needs a rebuild step
```

Signature: **`/talk SUBJECT <message>`**. Unlike `/chat`, which is a thread
attached to a card, `/talk` is attached to a **subject** — a long-lived topic
in the orchestrator's notes under the server's `-root`.

As you talk, the orchestrator maintains that subject's notes, so the knowledge
accumulates across sessions instead of being trapped in one card.

Requires the server to be started with `-root`, which is what enables the
orchestrator and MCP layer at all. See [setup](../server/setup.md).

Once a subject has been mentioned enough times — `-subject-threshold`, default
`4` — the orchestrator proposes giving it a dedicated MCP server.
