Type a slash command on its own line in any note and press **Enter**. The line
becomes a live **card** that streams its result in place and is persisted in
the note's markdown.

There are **15** commands. Source of truth:
`webview-editor/src/ai/commands.js`.

## Quick reference

| Command          | What it does                                                                     | Needs                    |
| ---------------- | -------------------------------------------------------------------------------- | ------------------------ |
| `/ask`           | Ask Claude a question — the answer streams into a card                           | Server                   |
| `/chat`          | Start a conversation with Claude — reply in the card to keep the thread           | Server                   |
| `/clean`         | Clean up & reorganize the whole page                                             | Server                   |
| `/search`        | Search your notebooks — `/search QUERY`                                          | — *(offline)*            |
| `/code`          | Start a Claude Code agent in a project on the paired laptop                       | `-allow-code`            |
| `/run`           | Run a shell command inside a project — `/run PROJECT <cmd>`                       | `-allow-exec`            |
| `/delete`        | Delete a project folder on the paired laptop — `/delete PROJECT`                  | `-allow-code`            |
| `/view`          | Preview a localhost dev server — `/view PORT`                                     | `-allow-view`            |
| `/record`        | Record microphone audio — keeps going in the background                           | — *(on-device)*          |
| `/talk`          | Chat about a subject — `/talk SUBJECT <message>`                                  | Server + `-root`         |
| `/ingest`        | File this page into your dashboard, then clear the page                           | Server                   |
| `/archive`       | Archive this page into the dashboard's Archived section                           | — *(on-device)*          |
| `/agg-tasks`     | Sweep a subject's notebook for action items, file one task card per item          | Server + `-root`         |
| `/pair`          | Pair a device by QR code or payload                                              | —                        |
| `/update-server` | Pull, rebuild and restart the Go server on the paired laptop                       | Server                   |

## How cards behave

Cards are hoisted into a long-lived **run registry**, so a running command
survives swiping between pages or swapping notebooks. Come back later and the
output is still streaming.

Bulky card bodies — a `/code` transcript, `/run` output, a `/clean` backup —
are stored in a separate `card_payloads` table rather than inline in the page
markdown, because the page's full markdown crosses the WebView bridge on every
keystroke. See [storage](../architecture/storage.md).

Cards that take typed input — the `/chat` follow-up box, `/run`'s stdin, `/code`'s
prompt — share one text box. It spans the card's full width, and its buttons (the
mic, `/run`'s interrupt and stop) sit **inside the box, in its bottom-right
corner**, where they stay as the box grows. Long text **wraps onto new lines and
the box grows taller** to keep all of it visible, up to a few lines' worth, after
which the box scrolls internally instead of pushing the card off screen. `Enter`
sends (it never inserts a newline), and expanding a card to its full-page view
gives you the same box with the same behavior.

Anything typed but not yet sent **follows the card**: expand a card mid-sentence
and the full-page box picks up where you left off, close the page and the card's
own box has it back. Only sending it (or deleting the card) clears it, so a
streaming answer or a collapsed card can't lose it either.

Getting back out of a full-page card is either the **Back arrow** in its header
or, on Android, the **system Back button** — which collapses the card back into
the note rather than leaving the page. With nothing expanded, Back does its
usual thing. The command keeps running either way; collapsing a card never stops
it.

### Talking into a card

The button in the bottom-right corner of a card's text box is a **mic**, not a
Send button — tapping it
starts [dictation](../start/the-pad.md#dictation) *and* drops the caret into that
card's box, so your words go to the card instead of the page. Tapping the mic
again while the caret is still in that box stops the session, which sends what
you dictated (stopping the mic always does the equivalent of pressing `Enter`
where the caret is).

With the mic already running elsewhere — in the page, or in another card — the
card's mic just moves the caret into its own box and keeps the session going, so
you can talk into a note, then into a card, without stopping and restarting.

`Enter` still sends by hand, as does saying **"system new line"**.
