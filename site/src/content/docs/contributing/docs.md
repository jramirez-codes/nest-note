The site is [Astro](https://astro.build/) + [Starlight](https://starlight.astro.build/),
living in `site/` as an independent sub-project.

```bash
cd site
npm install
npm run dev     # http://localhost:4321/ai-notepad/
```

## Adding a page

Drop a markdown file in the right directory under `site/src/content/docs/` with
`title` and `description` frontmatter. That's it.

```markdown
---
title: My page
description: One sentence, used for search results and social cards.
sidebar:
  order: 3
---
```

The `commands/`, `architecture/` and `contributing/` groups are
**autogenerated** — a new file appears in the sidebar with no config, ordered
by `sidebar.order`. The `Get started` and `Companion server` groups are
**explicit** in `astro.config.mjs`, because their reading order is pedagogical
and alphabetical ordering would scramble it. Adding a page there means adding
one line to the sidebar config.

### Declaring prerequisites

Don't hand-write "this needs a server" warnings. Declare them in frontmatter
and render the shared component:

```mdx
---
title: Projects
requiresServer: true
requiresFlag:
  - allow-code
  - allow-exec
---

import Requires from '../../../components/Requires.astro';

<Requires />
```

The schema lives in `site/src/content.config.ts`. This exists so the wording of
capability warnings is identical everywhere — an out-of-date `-allow-*` warning
is a security problem, not a typo. Note that using a component requires the
page be `.mdx`, not `.md`.

## Link rules

The site is served from a **sub-path** (`/ai-notepad/`). Starlight prefixes its
own chrome automatically, but nothing hand-written gets that for free. Two
rules:

**In markdown, always use relative file links** — pointing at the actual `.md`
file on disk, which your editor can follow:

```markdown
[flags](../server/flags.md)        ✅ becomes /ai-notepad/server/flags/
[flags](/server/flags/)            ❌ 404s in production — no base
[flags](/ai-notepad/server/flags/) ❌ works, but hardcodes the base
```

Astro does **not** rewrite markdown links on its own. `plugins/remark-doc-links.mjs`
does it: it resolves the relative path against the file's location, converts it
to a route, and prefixes `base`. That's why the base appears in exactly one
place (`astro.config.mjs`) instead of in forty pages — moving to a custom
domain stays a one-line change.

`starlight-links-validator` then runs against the rewritten routes and fails
the build on a broken target, so a typo can't reach production.

**In `.mdx`, component props are invisible to remark.** A `<LinkCard href=…>`
is JSX, not a markdown link, so it needs `withBase()`:

```mdx
import { withBase } from '../../lib/url';

<LinkCard title="Install" href={withBase('/start/install/')} />
```

**In `.astro` components, every `href` and `src` goes through `withBase()`.**

```astro
---
import { withBase } from '../lib/url';
---
<a href={withBase('/introduction/')}>Read the docs</a>
```

Before deploying, this should return nothing:

```bash
grep -rn 'href="/\|src="/' site/src --include=*.astro
```

**Images go in `src/assets/` and are imported**, never in `public/`, so Vite
emits a hashed base-correct URL. Reserve `public/` for `favicon.svg`,
`robots.txt` and `.nojekyll`.

## Gotchas

:::caution[Search doesn't work in dev]
Pagefind builds its index during `astro build` only. In `npm run dev` the
search box returns nothing — that's expected, not a bug. Test search with
`npm run build && npm run preview`.
:::

:::caution[Don't add Tailwind]
`@astrojs/tailwind` is deprecated in Astro 5+, and Tailwind v4's preflight
reset collides with Starlight's stylesheet, silently degrading its typography.
The landing page uses scoped `<style>` blocks instead. This intentionally
differs from the app's NativeWind setup — they're separate builds.
:::

:::note[Theme is generated]
`src/styles/catppuccin.generated.css` is produced from
`src/theme/catppuccin.js` at the repo root. Edit the palette there and run
`npm run gen:theme`. CI runs `npm run check:theme`, which fails if the
committed file is stale. Starlight variable mapping is hand-written in
`src/styles/theme.css` — edit that one freely.
:::

## Verifying before you push

```bash
npm run build && npm run preview
```

Browse from `http://localhost:4321/ai-notepad/` — **not** `/`, which 404s and
looks like a broken build. Click through the sidebar, toggle light/dark, and
run a search.

## Keeping the README honest

`README.md` at the repo root is a **pitch and repo map**, not a manual.
Anything operational belongs here instead. When you change behavior, update the
docs page; only update the README if the elevator pitch itself changed.

This split exists because the README had already drifted — it documented
`/run <cmd>` when the real signature is `/run PROJECT <cmd>`, and listed fewer
commands than `webview-editor/src/ai/commands.js` actually defines.
